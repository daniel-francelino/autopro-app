## 1. Resumo

O AutoPro é um SaaS B2B com **duas páginas públicas indexáveis de fato**: a landing (`/`) e `/pricing`. A landing está bem feita
no básico (um `h1`, canonical, Open Graph, JSON-LD, `lang="pt-BR"`, imagem com `alt` e dimensões). Os problemas estão no que
cerca a landing: não existe `robots.txt` nem `sitemap.xml`, telas de login e áreas internas não têm `noindex`, o título de
`/pricing` sai com a marca duplicada, há conteúdo de template de outro projeto no repositório, e o **FAQ de `/pricing` faz
afirmações que o produto não cumpre** — o que é ruim para o usuário, para o Google e pior ainda para IAs, que repetem o texto.

O maior ganho de tráfego não é técnico: **o site tem 1 página para ranquear**. Sem páginas por tema ("sistema para oficina
mecânica", "ordem de serviço para oficina", "NFS-e para oficina", "comissão de mecânico"), o SEO tem teto baixo.

**Nota (técnico): 6/10 · (conteúdo/cobertura de palavras-chave): 2/10 · (confiabilidade das afirmações públicas): 4/10.**

### O que já está bom

- `<html lang="pt-BR">` e `og:locale pt_BR` na landing; um único `h1` com `h2` por seção.
- Canonical + `og:url` + Twitter Card (`summary_large_image`) na home; `description` com ~138 caracteres.
- Imagem da landing com `alt`, `width`/`height`, `loading="lazy"`, `decoding="async"` e ~107 KB.
- `/` e `/pricing` **pré-renderizadas** (`routeRules`), ótimo para rastreamento e LCP; `/app/**` fora do prerender.
- Link "pular para o conteúdo", `aria-label` nos links de logo; PWA com manifest, `lang` e ícones maskable.

## 3. Plano de correção (ordem sugerida)

### Passo 1 — `robots.txt`, `sitemap.xml` e `noindex` (A1, A2, M6)

Instalar `@nuxtjs/robots` e `@nuxtjs/sitemap` (versões compatíveis com Nuxt 4 no momento da instalação; ambos usam o
`nuxt-site-config` que o `nuxt-og-image` já traz):

```ts
// nuxt.config.ts
modules: [/* ... */, '@nuxtjs/robots', '@nuxtjs/sitemap'],

site: {
  url: process.env.NUXT_PUBLIC_SITE_URL,   // resolve M6; falha o build de produção se vazio (ver Passo 2)
  name: 'AutoPro',
  defaultLocale: 'pt-BR'
},

robots: {
  disallow: ['/app', '/admin', '/api', '/login', '/forgot-password', '/reset-password',
             '/onboarding', '/checkout', '/subscription', '/403']
  // a política específica para crawlers de IA está na auditoria de GEO §5
},

sitemap: {
  exclude: ['/app/**', '/admin/**', '/login', '/forgot-password', '/reset-password',
            '/onboarding', '/checkout/**', '/subscription', '/403']
},

routeRules: {
  // ...regras atuais
  '/app/**':           { robots: false },
  '/admin/**':         { robots: false },
  '/login':            { robots: false },
  '/forgot-password':  { robots: false },
  '/reset-password':   { robots: false },
  '/onboarding':       { robots: false },
  '/checkout/**':      { robots: false },
  '/subscription':     { robots: false },
  '/403':              { robots: false }
}
```

`robots.txt` só bloqueia rastreamento; o `noindex` (meta + header `X-Robots-Tag` que o módulo aplica) é o que tira do índice.
Sem módulo, o equivalente mínimo é `public/robots.txt` estático + `routeRules: { '/app/**': { headers: { 'X-Robots-Tag': 'noindex, nofollow' } } }`.

`/signup`: manter indexável se a intenção for ranquear "criar conta"; recomendação: `noindex` até existir oferta clara de teste.

### Passo 2 — Títulos, metas e domínio (A3, M1, M2, M4, M5)

- **Composable `useSiteUrl()`** (`app/composables/useSiteUrl.ts`): devolve `runtimeConfig.public.siteUrl` sem barra final; em
  produção, **falha** (erro no build/SSR) se a variável estiver vazia, em vez de cair em `https://autopro.app`. Usar em `app.vue`,
  `index.vue`, `pricing.vue` e nas páginas novas.
- `/pricing`: `seo.title` do YAML vira `Planos e preços` (o template acrescenta a marca) **ou** a página usa `titleTemplate: '%s'`.
  Adicionar `link rel=canonical` e `og:url` com `useSiteUrl()`.
- `error.vue:133`: título sem `| AutoPro` (o template já põe).
- **Home**: `Sistema para oficina mecânica | AutoPro` (o Google corta ~60 caracteres); o slogan continua no `h1`/hero, com
  "sistema para oficina mecânica" no subtítulo imediatamente abaixo.
- `app.vue:56`: viewport `width=device-width, initial-scale=1, viewport-fit=cover`. Se o zoom quebrar telas internas no
  PWA/Capacitor, aplicar o viewport restritivo **só** no layout `app` (via `useHead` no `layouts/app.vue`).

### Passo 3 — Afirmações públicas e fonte única de planos (A6, M8)

### Passo 4 — Dados estruturados (M3, B3)

Na home, trocar o JSON-LD único por um `@graph` montado a partir de `usePlans()` e do FAQ:

```ts
const site = useSiteUrl()
const { plans } = usePlans()
useHead({ script: [{ type: 'application/ld+json', innerHTML: JSON.stringify({
  '@context': 'https://schema.org',
  '@graph': [
    { '@type': 'Organization', '@id': `${site}/#org`, name: 'AutoPro', url: `${site}/`,
      logo: `${site}/icons/icon-512x512.png` /* + contactPoint, sameAs quando existirem */ },
    { '@type': 'WebSite', '@id': `${site}/#website`, url: `${site}/`, name: 'AutoPro', inLanguage: 'pt-BR',
      publisher: { '@id': `${site}/#org` } },
    { '@type': 'SoftwareApplication', '@id': `${site}/#app`, name: 'AutoPro',
      applicationCategory: 'BusinessApplication', operatingSystem: 'Web, Android, iOS', inLanguage: 'pt-BR',
      offers: plans.map(p => ({ '@type': 'Offer', name: p.name, price: String(p.priceAmount), priceCurrency: 'BRL',
        url: `${site}/pricing`, category: 'subscription' })),
      publisher: { '@id': `${site}/#org` } }
    // + { '@type': 'FAQPage', mainEntity: [...] } a partir do FAQ visível
  ]
}) }] })
```

Validar no Rich Results Test e no validator.schema.org; conferir o HTML **sem JavaScript** (`curl`).

## 4. Estratégia de conteúdo (o maior ganho)

Hoje o site disputa uma palavra-chave genérica com uma URL. Proposta mínima (detalhada para o público brasileiro e IAs na
[auditoria de GEO §6](geo-audit-brasil.md#6-páginas-e-conteúdo-para-o-brasil)):

| Página nova | Intenção de busca | Observação |
|---|---|---|
| `/sistema-para-oficina-mecanica` | sistema para oficina mecânica | Principal |
| `/ordem-de-servico-oficina` | ordem de serviço oficina, OS digital, modelo de OS | Recurso central |
| `/comissao-mecanico` | como calcular comissão de mecânico | **Principal diferencial** do produto |
| `/controle-financeiro-oficina` | controle financeiro / fluxo de caixa oficina | Contas, parcelas, lucro |
| `/nota-fiscal-oficina` | NFS-e para oficina | Plano Fiscal; regra com fonte e data |
| `/estoque-pecas-oficina` | controle de estoque de peças | Recurso |
| `/guias/*` | guias práticos | Só com rotina de publicação |

Implementação: páginas em `app/pages/` com conteúdo em `content/paginas/*.md` (coleção nova `paginas`, tipo `page`), um
layout comum (hero com resposta direta, seções, FAQ da página, CTA para `/signup`, links internos), `routeRules` com
`prerender: true` para cada URL e entrada automática no sitemap. Cada página: `h1` com o termo, 600+ palavras úteis, captura
de tela real com `alt`, CTA, link para `/pricing` e para as outras páginas, data de revisão.
Páginas de comparação ("AutoPro vs planilha") convertem bem, mas só com teste real e fonte (GEO §6).

## 5. O que medir depois de corrigir

1. Cadastrar o domínio no **Google Search Console** (verificação por DNS) e no **Bing Webmaster Tools** (alimenta o Copilot); enviar o `sitemap.xml` nos dois.
2. **PageSpeed Insights** em `/` e `/pricing` (mobile): registrar LCP, CLS, INP *(não medido nesta auditoria)*. Meta: LCP < 2,5 s, CLS < 0,1, INP < 200 ms.
3. Indexação: `site:dominio` não deve listar `/login`, `/app`, `/admin`; "Páginas" no Search Console sem erros de rastreamento.
4. Card de compartilhamento no WhatsApp, LinkedIn e no depurador do Facebook.
5. Acompanhar consultas e páginas por 4–8 semanas antes de julgar o efeito.
